# Technical Terms Dictionary (Hard Concepts Explained Simply)

This dictionary translates complex distributed systems and database terminology into everyday analogies in plain English and conversational Sinhala, paired with their direct code locations in the Hitha platform.

---

## 📚 Complete Dictionary of Architecture Terms

| Term & Concept | Plain English Analogy | සරල සිංහල තේරුම (Plain Sinhala) | HITHA Codebase Location |
|:---|:---|:---|:---|
| **Dual-Plane Logging** | **Two-Road Traffic Separation**: Sending high-frequency debug traces to local files, while keeping only legally-binding audit records in the database. | **ලොග් වර්ග දෙක වෙනම පාරවල් දෙකකට බෙදීම**: සාමාන්‍ය දහස් ගණන් operational debug logs Server Disk එකේ file වලට ලියන අතර, නීතිමය සහ මුදල් ගනුදෙනු logs පමණක් Database එකට යැවීම. Database එක logs වලින් පිරිලා slow වීම වළක්වයි. | `logback-spring.xml` + `AuditLogServiceImpl.java` |
| **Log Rolling Policy** | **File Size & Time Auto-Chunking**: Closing the current log file and starting a fresh one whenever 100MB or 1 hour is reached, compressing the old one into `.gz`. | **ෆයිල් එක ලොකු වෙනකොට පැයෙන් පැයට හෝ 100MB වලින් zip කර අලුත් file එකක් පටන් ගැනීම**: එකම text file එක gigabytes ගණන් ලොකු වෙන්න නොදී ඉබේ zip කර අලුත් file එකක් හැදීම. | `logback-spring.xml` (`SizeAndTimeBasedRollingPolicy`) |
| **Disk Cap / Auto-Eviction** | **Automatic Storage Safety Valve**: Enforcing a maximum disk limit (5GB) and age (14 days), deleting the oldest files automatically when the limit is breached. | **ඉඩ පිරෙන්න නොදී ස්වයංක්‍රීයව මකා දැමීම**: Server එකේ hard disk එක 100% full වෙලා backend එක crash නොවීමට, logs folder එක 5GB පිරුණු සැනින් හෝ දින 14ක් පැරණි වූ සැනින් පරණ zip files ඉබේම delete වීම. | `totalSizeCap=5GB` & `maxHistory=14` in `logback-spring.xml` |
| **MDC (Mapped Diagnostic Context)** | **Thread Context Tagging**: Attaching metadata (user ID, client IP, correlation ID) to the execution thread so every log statement prints those details automatically. | **ලොග් එකකට හැඳුනුම්පත් ලේබල් ඇලවීම**: Request එකක් ආපු සැනින් ඒ request එකේ Correlation ID, User ID, Client IP එක thread එකට ලේබල් කිරීම. එම thread එක ඇතුළේ ලියවෙන ඕනෑම log එකක මේ තොරතුරු ඉබේම print වේ. | `CorrelationIdFilter.java` injecting MDC context |
| **Correlation ID** | **Unique Request Tracking Number**: A single UUID passed across all logs, microservices, and response headers to trace one user action from start to finish. | **Request එකකට දෙන සුවිශේෂී ට්‍රැකින් අංකය**: User කෙනෙක් බටන් එකක් click කළ විට හැදෙන unique UUID අංකය. Error එකක් ආ විට මේ එක ID එකෙන් frontend, backend, සහ database logs සේරම පහසුවෙන් සොයාගත හැක. | `CorrelationIdFilter.java` (`X-Correlation-Id`) |
| **Virtual Threads (Java 21)** | **Ultra-Lightweight Concurrency**: JVM-managed lightweight threads consuming only a few bytes of memory, allowing 100,000+ simultaneous operations without thread starvation. | **Java 21 හි ඇති සුපිරි සැහැල්ලු ත්‍රෙඩ්**: සාමාන්‍ය OS thread එකක් 1MB මතකය ගන්නා විට, Virtual Thread එකක් ගන්නේ bytes කිහිපයක් පමණි. එකවර ලක්ෂ ගණනක් users ලාට සේවය දිය හැක. | `spring.threads.virtual.enabled=true` |
| **Hash-Chain Race Condition** | **Sequence Collision Under Load**: When concurrent threads read the same uncommitted parent hash before any transaction finishes, causing parallel branches and breaking cryptographic integrity. | **එකම වෙලාවේ දෙන්නෙක් එකම අංකය ගැනීමට පොරකෑම**: Virtual threads 20ක් එකම මිලි තත්පරයේ audit logs ලියද්දී, සේරම thread එකම previous hash එක කියවා ගැනීම නිසා cryptographic chain එක දෙබල වී (fork) සත්‍යතාවය බිඳවැටීම. | Fixed in `AuditLogServiceImpl.java` using `ReentrantLock` (`0dcb3b6`) |
| **ReentrantLock** | **Explicit Thread Turn-Taker**: A Java concurrency lock ensuring only one thread can execute a critical code block at any given millisecond. | **පෝලිමේ එකින් එක යැවීමේ Java අගුල**: කවුරු ආවත් එක වෙලාවකදී එක thread එකකට පමණක් code block එක run කිරීමට ඉඩ දී, අනික් අයව පෝලිමේ තබන Java thread lock එකක්. | `AuditLogServiceImpl.hashChainLock` |
| **HikariCP Connection Pool** | **Database Connection Vault**: A fixed set of 8 pre-opened, reusable database connections shared across all incoming user requests. | **Database එකට ඇති සීමිත ඇමතුම් මාර්ග 8**: Backend එක සහ PostgreSQL අතර ඇති සීමිත සම්බන්ධතා 8. එකවර requests 100ක් ආවොත්, මේ 8 දෙනා ඉක්මනින් වැඩ අවසන් කර ඊළඟ අයට ඉඩ දිය යුතුය. | `maximum-pool-size=8` in `application.yml` |
| **Connection Pool Exhaustion** | **Database Line Congestion**: A crash where all 8 database connections are occupied by slow queries or bot floods, causing all other requests to fail with HTTP 500. | **Database මාර්ග 8ම හිරවීම නිසා සර්වර් එක හිරවීම**: Hacker කෙනෙක් තත්පරයට requests 200ක් එවූ විට, connections 8ම තත්පර කිහිපයකින් lock වී මුළු HITHA platform එකම අක්‍රිය වීම. | Prevented in LOG-03 via `AuditAuthenticationEntryPoint` (`be9630d`) |
| **Sliding Window Rate Limiter** | **Moving 60-Second Quota Bouncer**: An algorithm that tracks request timestamps over the last 60 seconds to ensure a client never exceeds an allowed burst threshold. | **විනාඩියක කාල පරාසයක් බලන සීමා පාලකය**: ඕනෑම තත්පරයක සිට ආපස්සට ගෙවුණු තත්පර 60 ඇතුළත එකම IP එකකින් request කීයක් ආවාදැයි බලා, නියමිත ගණන (5) පැන්න විට අමතර ඒවා block කිරීම. | `AuditAuthenticationEntryPoint.java` |
| **GIN Index** | **Heavy Multi-Key Search Index**: A PostgreSQL index that deconstructs every word inside a JSONB column; excellent for deep text searching but heavily penalizes write speed (4x-8x slower). | **JSON ඇතුළේ හැම වචනයක්ම සොයන බරැති Index එක**: JSON එකක් ඇතුළේ ඇති හැම අකුරක්ම index කරන බරැති index එකක්. කියවීමට හොඳ වුවත්, අලුතින් record එකක් දමන විට database එක 4x-8x පමණ slow කරයි. | Dropped from `audit_logs.raw_payload` in LOG-04 (`a1194c7`) |
| **BRIN Index (Block Range Index)** | **Ultra-Compact Range Index**: An index storing only the minimum and maximum values for blocks of disk pages, taking 99% less disk space than B-Trees. | **පොතේ පිටු මිටි වල අංක ලකුණු කරන සැහැල්ලු Index එක**: දහස් ගණන් rows වෙන වෙනම index නොකර, disk blocks වල ඇති අවම සහ උපරිම දිනය පමණක් ලකුණු කර තබා ගැනීම. B-Tree එකකට වඩා 99% ක් කුඩාය; Date range searches වලට අතිශය වේගවත්ය. | Added on `audit_logs(created_at)` in LOG-04 (`004-optimize-audit-logs-indexes.yaml`) |
| **Composite B-Tree Index** | **Multi-Column Fast-Lane**: An index combining two columns together (`created_at DESC, action`) so sorting and filtering bypass full-table scans. | **තීරු දෙකක් එකතු කර හදන වේගවත් සෙවුම් පාර**: Date එකෙන් sort කර action එකෙන් filter කරන විට, database එකේ මුළු table එකම scan නොකර ක්ෂණිකව records අහුලා ගැනීමට තීරු දෙකම එකතු කර සාදන index එක. | Added on `audit_logs (created_at DESC, action)` in LOG-04 |
| **TTL Cache (Time-To-Live)** | **Temporary In-Memory Snapshot**: Storing heavy query results (like dashboard counters) in application RAM for 60 seconds to serve repeat visits instantly without hitting the database. | **නියමිත තත්පර ගණනකට පමණක් මතකයේ තබා ගැනීම**: Dashboard count queries වල උත්තරය තත්පර 60ක් RAM එකේ තබාගෙන, ඊළඟ තත්පර 60 ඇතුළත DB එකට නොගොස් ක්ෂණිකව උත්තරය දීම. | `AdminActivityLogServiceImpl.java` (`STATS_CACHE_TTL_MS`) |
| **JSON Lines (JSONL)** | **One-Record-Per-Line Format**: A streaming text format where each line is an independent JSON object, avoiding out-of-memory errors on large datasets. | **එක පේළියට එක JSON එක බැගින් ලියන format එක**: සාමාන්‍ය JSON එකක මුළු file එකම parse කළ යුතු වුවත්, JSONL වල එක පේළියක එක audit log එකක් ඇති නිසා gigabytes ගණන් logs වුවත් memory පිරෙන්නේ නැතිව stream කර කියවිය හැක. | `AuditLogArchiveServiceImpl.java` |
| **GZIP Stream Compression** | **On-the-Fly Byte Shrinker**: Compressing data directly as it is being written into a byte stream, reducing size by 85%-90% without temporary disk files. | **ලියවෙන ගමන්ම zip කරන තාක්ෂණය**: Data ලියා ඉවර වී zip කරනවා වෙනුවට, ලියවෙන අකුරෙන් අකුර ඒ මොහොතේදීම zip කර (85% කින් කුඩා කර) memory එක ඉතිරි කිරීම. | `GZIPOutputStream` in `AuditLogArchiveServiceImpl.java` (`45cc888`) |
