# Technical Terms & Architecture Glossary

This glossary defines core distributed systems, database, and telemetry terminology used across the HITHA engineering platform. Each term includes an everyday engineering analogy, its concrete operational definition, and its direct codebase implementation.

---

## 📚 Complete Dictionary of Architecture Terms

| Term & Concept | Plain English Analogy | Technical Definition | HITHA Codebase Location |
|:---|:---|:---|:---|
| **Dual-Plane Logging** | **Two-Road Traffic Separation**: Sending high-frequency debug traces to local files, while keeping only legally-binding audit records in the database. | Architectural separation of high-volume operational runtime traces (Plane A, rolling local files capped at 5GB) from immutable, legally-binding clinical audit logs (Plane B, PostgreSQL partitioned table + Cloudflare R2). | `logback-spring.xml` + `AuditLogServiceImpl.java` |
| **Log Rolling Policy** | **File Size & Time Auto-Chunking**: Closing the current log file and starting a fresh one whenever 100MB or 1 hour is reached, compressing the old one into `.gz`. | `SizeAndTimeBasedRollingPolicy` triggering hourly or 100MB chunk boundaries, compressing evicted log segments into gzip format without blocking the active logging thread. | `logback-spring.xml` (`SizeAndTimeBasedRollingPolicy`) |
| **Disk Cap / Auto-Eviction** | **Automatic Storage Safety Valve**: Enforcing a maximum disk limit (5GB) and age (14 days), deleting the oldest files automatically when the limit is breached. | Automated FIFO disk quota enforcement that permanently evicts log files older than 14 days or whenever the cumulative directory size exceeds 5GB. | `totalSizeCap=5GB` & `maxHistory=14` in `logback-spring.xml` |
| **MDC (Mapped Diagnostic Context)** | **Thread Context Tagging**: Attaching metadata (user ID, client IP, correlation ID) to the execution thread so every log statement prints those details automatically. | Thread-local metadata store in SLF4J/Logback automatically injected into every asynchronous logging layout pattern (`correlationId`, `actorId`, `actorRole`, `clientIp`, `jurisdiction`). | `CorrelationIdFilter.java` injecting MDC context |
| **Correlation ID** | **Unique Request Tracking Number**: A single UUID passed across all logs, microservices, and response headers to trace one user action from start to finish. | Monotonically propagated distributed trace UUID injected at the HTTP perimeter (`X-Correlation-Id`) to correlate web, backend, and database queries. | `CorrelationIdFilter.java` (`X-Correlation-Id`) |
| **Virtual Threads (Java 21)** | **Ultra-Lightweight Concurrency**: JVM-managed lightweight threads consuming only a few bytes of memory, allowing 100,000+ simultaneous operations without thread starvation. | User-mode JVM lightweight threads that unmount from carrier OS threads during blocking I/O, eliminating thread pool exhaustion during long-polling or DB waits. | `spring.threads.virtual.enabled=true` |
| **Hash-Chain Race Condition** | **Sequence Collision Under Load**: When concurrent threads read the same uncommitted parent hash before any transaction finishes, causing parallel branches and breaking cryptographic integrity. | Concurrency vulnerability where parallel threads read an uncommitted parent hash in `audit_logs`, creating competing cryptographic forks. | Fixed in `AuditLogServiceImpl.java` using `ReentrantLock` (`0dcb3b6`) |
| **ReentrantLock** | **Explicit Thread Turn-Taker**: A Java concurrency lock ensuring only one thread can execute a critical code block at any given millisecond. | Explicit JVM mutex lock used to serialize hash generation and repository save across concurrent virtual threads. | `AuditLogServiceImpl.hashChainLock` |
| **HikariCP Connection Pool** | **Database Connection Vault**: A fixed set of 8 pre-opened, reusable database connections shared across all incoming user requests. | Production JDBC connection pool maintaining a fixed allocation of 8 persistent PostgreSQL connections to maximize query throughput and prevent connection churn. | `maximum-pool-size=8` in `application.yml` |
| **Connection Pool Exhaustion** | **Database Line Congestion**: A crash where all 8 database connections are occupied by slow queries or bot floods, causing all other requests to fail with HTTP 500. | Denial-of-Service condition where incoming requests exhaust available JDBC connections, causing cascading 30-second timeouts across clinical APIs. | Prevented in LOG-03 via `AuditAuthenticationEntryPoint` (`be9630d`) |
| **Sliding Window Rate Limiter** | **Moving 60-Second Quota Bouncer**: An algorithm that tracks request timestamps over the last 60 seconds to ensure a client never exceeds an allowed burst threshold. | High-resolution rate limiting algorithm tracking IP request timestamps in a circular buffer, dropping burst floods without database writes. | `AuditAuthenticationEntryPoint.java` |
| **GIN Index** | **Heavy Multi-Key Search Index**: A PostgreSQL index that deconstructs every word inside a JSONB column; excellent for deep text searching but heavily penalizes write speed (4x-8x slower). | Generalized Inverted Index indexing every token in a JSONB document, incurring severe 4x-8x write amplification penalties under high audit ingestion. | Dropped from `audit_logs.raw_payload` in LOG-04 (`a1194c7`) |
| **BRIN Index (Block Range Index)** | **Ultra-Compact Range Index**: An index storing only the minimum and maximum values for blocks of disk pages, taking 99% less disk space than B-Trees. | Block Range Index storing page-range metadata for naturally sequenced append-only log data, occupying 99% less disk space than traditional B-Tree indexes. | Added on `audit_logs(created_at)` in LOG-04 (`004-optimize-audit-logs-indexes.yaml`) |
| **Composite B-Tree Index** | **Multi-Column Fast-Lane**: An index combining two columns together (`created_at DESC, action`) so sorting and filtering bypass full-table scans. | Multi-column index covering ordered timestamp scans filtered by audit action types, eliminating runtime sort operations. | Added on `audit_logs (created_at DESC, action)` in LOG-04 |
| **TTL Cache (Time-To-Live)** | **Temporary In-Memory Snapshot**: Storing heavy query results (like dashboard counters) in application RAM for 60 seconds to serve repeat visits instantly without hitting the database. | Volatile in-memory cache holding pre-aggregated operational statistics for 60 seconds, preventing redundant `COUNT(*)` database scans. | `AdminActivityLogServiceImpl.java` (`STATS_CACHE_TTL_MS`) |
| **JSON Lines (JSONL)** | **One-Record-Per-Line Format**: A streaming text format where each line is an independent JSON object, avoiding out-of-memory errors on large datasets. | Line-delimited JSON streaming format where each record is independently parseable, enabling low-memory chunked archival. | `AuditLogArchiveServiceImpl.java` |
| **GZIP Stream Compression** | **On-the-Fly Byte Shrinker**: Compressing data directly as it is being written into a byte stream, reducing size by 85%-90% without temporary disk files. | Streaming compression pipeline encoding raw JSONL records directly into gzip format in memory, reducing network payload sizes by up to 90%. | `GZIPOutputStream` in `AuditLogArchiveServiceImpl.java` (`45cc888`) |
| **SHA-256 Manifest** | **Cryptographic Tamper-Proof Seal**: A companion metadata digest recording the exact cryptographic checksum of an exported archive to prove it was never tampered with. | Companion cryptographic manifest certifying the archive checksum, record count, and start/end hash chain boundaries for forensic verification. | `AuditArchiveBundle.getArchiveSha256()` |
| **WORM Storage** | **Write Once, Read Many Cloud Vault**: Cloud object storage locked so that uploaded files cannot be modified, deleted, or overwritten by anyone for 7 years. | Object-level immutability policy locking Cloudflare R2 buckets against modification, premature deletion, or administrative tampering for 7 years. | Cloudflare R2 Object Storage with Object Lock |
| **Hive Partitioning** | **Folder-By-Time Hierarchy**: Organizing cloud files into directory paths like `year=YYYY/month=MM/jurisdiction=LK/` so external tools only scan relevant folders. | Directory partition convention structuring object keys for efficient partition pruning and BigQuery/Athena querying. | Formatted in `AuditArchiveBundle.getObjectKey()` |
| **Pessimistic Locking** | **Exclusive Database Row Lock**: A database locking mechanism (`SELECT FOR UPDATE`) that forces concurrent users to wait in line so two people never book the same slot. | Row-level database lock acquiring exclusive transaction ownership, ensuring concurrent reservation requests are strictly serialized. | `WaitingQueueDispatcherScheduler` & `BookingConfirmationService` |
| **Idempotency** | **Duplicate-Proof Execution**: Guaranteeing that executing the same network request multiple times produces the exact same result without double-charging. | Transactional guarantee ensuring duplicate webhook retries or API calls yield identical state without duplicate balance deductions. | `PaymentServiceImpl.handleNotify` |
| **Escrow Vault** | **Intermediate Trust Holding**: Locking patient funds in an intermediary account until the doctor completes the consultation call. | Custodial double-entry ledger holding patient booking payments in escrow until explicit clinical consultation completion. | `DoctorWalletService.creditEscrow(booking)` |
| **Server-Sent Events (SSE)** | **Persistent One-Way Web Push**: A lightweight persistent HTTP connection pushing real-time events from server to browser without WebSockets overhead. | Unidirectional HTTP streaming protocol delivering asynchronous domain events (incoming call rings, payment confirmations) to clients. | `SseRegistryService` & `SseDomainEventListener` |
